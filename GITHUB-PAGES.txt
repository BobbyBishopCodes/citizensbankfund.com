GITHUB PAGES — PORTFOLIO BUILD AND RELEASE PREPARATION

Project requirement
  Design all website features for static GitHub Pages hosting. Run portfolio
  imports and quote calculations at build time, locally or in GitHub Actions.
  The published site must not need a local Node server or portfolio admin token.

Current state
  Everything is prepared locally. No workflow has been pushed or run on GitHub.
  No GitHub settings, secrets, schedules, Pages deployment, or DNS have changed.
  The /portfolio screen reads /data/portfolio.json and shows holdings, gains,
  estimated income, allocations, and pricing dates. The Home page also reads
  /data/portfolio.json for value, gain vs. $100,000 starting capital, and security count.

  .github/workflows/validate-pages.yml is MANUAL-ONLY (workflow_dispatch).
  It tests and builds a preview, then uploads a downloadable artifact for seven
  days. It has read-only repository permissions, pinned action revisions, no
  deployment job, and no push/PR/scheduled trigger. Uploading an Actions artifact
  does not publish a website. Treat the artifact as shareable portfolio data;
  it contains holdings and calculated metrics, not confidential records.

Prepare a holdings update
  Run from the project root with Node 24+:

  npm run portfolio:prepare -- "C:\Users\Roberto\Downloads\RJFPortfolio 9.24.2026.csv" --as-of 2026-09-24

  This creates content/portfolio/holdings.json from the COMPLETE holdings CSV.
  Review the printed warnings and this file before committing it. Update the
  path and date for each new export. Earlier holdings dates are rejected;
  same-date corrections and repeated imports are allowed. Invalid files do not
  replace the prior input. Removed positions disappear from the new snapshot.

  Only selected holdings fields are retained: name, ticker, quantity, product
  type, reported value/price, amount invested, optional cost basis and income.
  Unknown CSV columns, original filename, private source fields and account
  metadata are omitted. Holdings and investment amounts are still sensitive if
  you do not intend them to be public: review before pushing a public repository.
  The original CSV is not copied into the repository or artifact by this command.
  Back up original CSVs privately; this command does not archive them.

  GitHub runners read the committed holdings.json. They cannot read Downloads
  or .local/portfolio on your computer. The earlier local import command alone
  does NOT update the input used by the static build.

Test without publishing or using any API key
  npm test
  npm run build:preview
  node scripts/check-pages-preview.mjs

  The complete static preview is .local/pages-preview/.
  Its portfolio output is .local/pages-preview/data/portfolio.json.
  The preview build leaves docs/ untouched. The normal npm run build now creates
  portfolio/index.html and data/portfolio.json in docs/ for GitHub Pages hosting.

  Preview build always uses CSV snapshot prices, even if .env contains a key.
  It preserves the actual quote/holdings dates and reports snapshot coverage.
  Serve the directory with an HTTP static file server and open /portfolio/ to
  inspect the screen. Vite development also serves snapshot data from the
  prepared holdings file; CSV preparation updates the local page automatically.

Optional local market-data validation
  Set FINNHUB_API_KEY in your existing .env, keeping its other values.
  After building the preview, run:

  npm run portfolio:export -- market
  node scripts/check-pages-preview.mjs

  This replaces ONLY the preview's data/portfolio.json after all securities
  receive valid quotes. Missing keys, failed symbols, malformed data, provider
  errors or unsafe totals fail the export and leave the previous file intact.
  Closed-market quotes may be old; they retain their actual timestamps and are
  labelled stale. No missing quote is silently replaced in market mode.
  Snapshot mode deliberately uses broker values and makes zero API requests.

  The JSON includes calculatedAt, holdingsAsOfDate, priceAsOf for each position,
  quote coverage, and a publication.mode flag. calculatedAt is the build time,
  not the market-data timestamp. Future pages must recompute freshness from
  priceAsOf at display time; a saved fresh-quote label becomes stale over time.

If your npm launcher is broken
  node scripts/portfolio-static.mjs prepare "path.csv" --as-of 2026-09-24
  node --env-file-if-exists=.env scripts/portfolio-static.mjs export market

  The local preview build can also run directly in this order:
  node node_modules/typescript/bin/tsc -b
  node node_modules/vite/bin/vite.js build --outDir .local/pages-preview
  node scripts/build-pages.mjs .local/pages-preview
  node scripts/portfolio-static.mjs export snapshot
  node scripts/check-pages-preview.mjs

GitHub setup at release (not performed now)
  1. Commit/push the reviewed code, lockfile, workflow and prepared holdings file.
     Exclude .env, raw CSV archives and .local. Merely pushing this workflow
     does not run it or publish the preview. Follow the existing Pages publishing
     rules if Pages is already enabled; this workflow does not change them.
  2. Add FINNHUB_API_KEY as a repository Actions secret, not as a VITE_ variable
     and not inside a committed file. The admin token is not needed here.
  3. Once the workflow exists on the default branch, manually run "Validate
     GitHub Pages build (no deployment)" from Actions. Choose snapshot first,
     then market to validate real provider access. Download/review the artifact.
     Only the quote-export step receives FINNHUB_API_KEY.
  4. When publishing is explicitly approved, add the Pages deployment job and
     switch Settings > Pages > Source to GitHub Actions. Deploy the WHOLE static
     output, including routes, assets, .nojekyll, CNAME and data/portfolio.json.
     Retain the citizensbankfund.com domain and existing routes. Do not deploy
     just the JSON file: a Pages deployment replaces the site artifact.
  5. At that time add a schedule and holdings-change trigger to the publishing
     workflow. Require successful market export and artifact validation before
     deployment. A failed refresh must leave the existing published site intact.
     Enable manual refresh as well; use deployment concurrency to avoid races.
  6. The Portfolio screen already reads /data/portfolio.json, checks for newer
     files every five minutes while visible, and reassesses quote freshness
     every minute. It retains the last loaded data if an update fails. The Home
     page reads the same data and checks for updates every five minutes.

  Schedules are periodic snapshots, not guaranteed live streaming. GitHub can
  delay scheduled runs; public-repository schedules can be disabled after 60
  days without repository activity. Provider delays are independent of Actions.
  Exact refresh frequency and market-hours scheduling will be chosen at release.
